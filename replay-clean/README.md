# replay-clean: replay of `replay-2026-10-26` in a fresh container

The 2026-10-25 runs in `replay-2026-10-26/` were made on the author's workstation, with JDKs, the Maven
repository for the Part B build and other host state already present (`replay-2026-10-26/README.md`,
"Toolchain" and interpretation 33). This directory records a replay of Parts A and B of that bundle in
a disposable linux/arm64 container built from a pinned base image, with both JDKs installed from
checksum-verified Eclipse Temurin archives and the records cloned from GitHub at commit
`d059baf95c8a21850a0b5d9d08ef07128d636ed2`. Part C is not run (`replay.sh` no longer runs it).

Result in one line: Part A reproduced in all 24 cells (same pass/fail counts and the same attempt
counts in every run); Part B reproduced the patched revision (0/20 per JDK) but not the published
counts of the hooked `dev` cells, and the unhooked `dev` revision failed 4/50 (JDK 8) and 2/50
(JDK 11) under CPU contention where the published runs record 0/50 and 0/50. Details:
[COMPARISON.md](COMPARISON.md).

## Toolchain manifest and `--require-toolchain`

`toolchain.json` names the base image digest, the image id of the executed build, both JDK archives
with URL and sha256, the Maven version, wrapper and distribution checksums, the Python version and the
pinned commits. Its `enforce` block holds the exact values that `replay.sh --require-toolchain` compares:
the full `java -version` output of both JDKs, `python3 --version`, the six apache/seatunnel commits in
the script, the wrapper `distributionUrl` at the four Part A and B revisions, the maven-wrapper 3.1.0
jar sha1 and the Maven 3.8.4 distribution zip sha256 (the zip's sha1 equals Maven Central's `.sha1`).

```
cd replay-2026-10-26
./replay.sh --part all --require-toolchain ../replay-clean/toolchain.json
```

Any difference stops the script with exit status 3; without the option `replay.sh` behaves as before.
The option was added after this replay (fifth revision of `replay.sh`, 2026-10-26). The replay itself
ran the fourth-revision script from `d059baf` (sha256 `4b612c5de438...`), so it was not enforced during
the runs; the values in `enforce` were taken from the replay's own records (`out/env/java-version.txt`,
`out/env/tools.txt`, `out/bundle/logs/partA/maven-version.txt`, `out/bundle/logs/setup/`). As before,
`replay-2026-10-26/results.json` keeps `sha256_as_run` for the version that produced the 2026-10-25 runs
and notes the revision.

`selftest_require_toolchain.sh` (records in `out-selftest/`, replay.sh sha256 `96a75a75a21e...`,
toolchain.json sha256 `b7172748fe89...`) ran in the replay image:

1. `./replay.sh --part A --prepare-only --require-toolchain ../replay-clean/toolchain.json`: all checks
   matched (10 lines `toolchain manifest: ... matches`), exit 0.
2. The same with a manifest whose `jdk8_java_version` is the Oracle 1.8.0_172 of the published runs:
   `FATAL: toolchain mismatch for jdk8_java_version`, exit 3, before apache/seatunnel was cloned.

An earlier execution of the self-test (06:06:41-06:08:13, same image, same `replay.sh` and
`toolchain.json`) gave the same two results (exit 0, exit 3). That version of the script copied the
whole `logs/setup` directory of the bundle copy, including the published setup records, into its output;
the script was changed to copy only the records each case writes, and its output directory was replaced
by the one from the second execution.

The published 2026-10-25 runs would not pass this manifest (different JDK builds and Python), which is
the point of recording it: a replay that passes the check used the toolchain of this replay.

## Limits

- The apt packages in the image (git, curl, python3 and the rest) are not pinned to versions; a rebuild
  can install newer Ubuntu updates and gets a different image id. The installed versions are listed in
  `out/env/tools.txt`. Python is checked by `--require-toolchain`.
- The container ran on the same host as the published runs, inside the Docker Desktop VM; other
  activity on the host was not stopped or recorded. A second physical machine was not used.
- Part B is one loop per cell, as in the published bundle.
- Part C was not run (see `replay-2026-10-26/harness/historical-part-c/README.md`).
